## Context

ForumHub 在 `ContentView` 首次任务和 `scenePhase == .active` 时恢复来源会话，并以 30 秒窗口避免短时间内重复恢复。NGA 使用 WebKit Cookie、共享 HTTP Cookie Storage 与 Keychain；V2EX 同时存在 API Personal Access Token 和独立的 Web Cookie 会话，只有后者能够执行网页每日奖励动作。

签到会修改远端账号状态，不能成为 `restoreSession()` 的隐式副作用。两站也没有共同的稳定签到协议：NGA 暴露 App API 动作，V2EX 依赖带动态 `once` 的网页流程。当前仓库只有 NGA 接口索引和 V2EX 历史流程，没有两站当前登录态成功、已完成及失败响应的脱敏 Fixture，因此必须先建立证据门禁。

## Goals / Non-Goals

**Goals:**

- 在用户明确启用后，于应用启动和经过节流的前台恢复时检查 NGA、V2EX 每日签到。
- 保持登录恢复、来源适配、协调状态和账户展示职责分离。
- 以真实脱敏响应 Fixture 驱动解析与错误分类；未知响应 fail closed。
- 防止并发重复执行，区分已签到、成功签到、不可用会话、可重试失败和不安全响应。
- 不阻塞首页内容加载，不把普通网络或解析错误误判为凭证过期。

**Non-Goals:**

- 不提供 iOS 后台定时签到，也不保证应用未运行时完成签到。
- 不把 V2EX API Token 转换成 Web Cookie，或用 Token 请求网页奖励。
- 不统一 NGA 与 V2EX 的原始响应模型、Cookie 合约或服务端日期规则。
- 不支持 LINUX DO 签到，不改变 Feed、帖子详情或共享领域模型。
- 不在缺少真实响应证据时通过字符串猜测执行远端写操作。

## Decisions

### 1. 真实响应 Fixture 是启用写入与最终验收门禁

实现顺序固定为先在已授权的真实账号会话中采集：NGA `get_stat` 的未签到/已签到响应、NGA `check_in` 成功及可安全获得的重复结果、V2EX `/mission/daily` 的可领取/已领取页面、领取动作响应及失效会话跳转。采样内容必须删除 Cookie、UID、用户名、余额、动态 `once` 等身份或一次性信息，并用等价占位值保持结构。

真实 Fixture 未齐全时允许先开发纯解析器、请求服务接缝、协调、偏好、生命周期和账户 UI，并可使用受控合成或公开文档驱动 Fixture 覆盖确定的结构。此类 Fixture 必须在文件名或文件头明确标注来源与证据等级，不得冒充真实服务端样本。

真实 Fixture 仍是启用真实写入与最终验收的硬门禁：只有经真实证据明确确认“当前周期未完成”的响应结构，才可以让生产路径到达远端写请求；没有证实的状态一律分类为未知并 fail closed。2026-07-23 已在授权 V2EX Web Session 中确认“可领取页面 → 唯一 `input onclick` 动作 → 已领取结果 → 独立再次访问仍已领取”的真实安全链，因此 V2EX 子门禁可按该严格结构解除；NGA 仍缺少可稳定解释的未签到与成功证据，production 写入继续不可达。V2EX 失效会话和完整重定向链仍待后续采样，不影响未知响应 fail closed，也不代表整体验收完成。

选择“先建立安全接缝、后用真实证据解锁写入”而不是等待全部样本后才开始开发，是为了让可确定的架构与测试工作继续推进，同时避免历史文档或合成样本错误授权远端写操作。

### 2. 签到协调独立于会话恢复

新增一个上层每日签到协调对象，在 `AuthSessionRegistry.restoreAll()` 完成后异步触发。协调对象只接收来源级“是否具备合格会话”和签到服务，不读取 Cookie 或 Token。启动与前台恢复共用同一入口；前台事件经过节流，来源切换不额外触发。

选择独立协调而不是扩展 `restoreSession()`，是因为恢复是凭证读取/验证，签到是用户可关闭的远端写行为，两者必须拥有不同的失败与取消语义。

### 3. 来源专属服务共享结果语义，不共享远端模型

NGA 与 V2EX 各自负责请求构造、原始响应解析、服务端状态确认与来源错误映射。协调层只消费统一结果：`checkedInNow`、`alreadyCheckedIn`、`ineligibleSession`、`retryableFailure`、`blockedForCurrentWindow`。具体类型名可在实现中沿用项目命名调整，但不得把原始字段暴露给 View。

选择共享结果而不是通用签到 HTTP 协议，是为了保留数据源边界，同时让账户 UI 和生命周期协调不出现页面解析分支。

### 4. NGA 先读状态，明确未签到后才写

NGA 服务使用已经恢复到共享 HTTP Cookie Storage 的会话访问 `get_stat`。仅当 Fixture 驱动的解析器明确确认“当前服务端周期未签到”时调用 `check_in`，然后解析写响应或重新查询状态确认。已签到、未知结构、频率限制及鉴权不明确时不发送写请求。

选择先读后写，是因为仓库文档明确提示签到可能有频率限制；单纯依赖本地日期不能覆盖多设备或重装场景。

### 5. V2EX 只接受页面签发的严格同源领取动作

V2EX 服务要求 `hasWebSession == true`，加载 `/mission/daily` 后由 HTML 解析器区分可领取、已领取和未知页面。真实页面签发的领取控件是唯一 `input[type=button]`，其领取文案为“领取 … 铜币”，`onclick` 只允许有限语法 `location.href = '<URL>';`；解析器不得执行或宽松解释任意 JavaScript。提取出的 URL 还必须是 HTTPS、主机严格等于 `www.v2ex.com`、路径严格等于 `/mission/daily/redeem`，并且 query 只包含一个非空动态 `once`。领取请求至多执行一次，随后必须独立重新读取 `/mission/daily` 并精确确认“每日登录奖励已领取”。

Token-only 连接返回不具备资格，不降级为 Token 请求。选择动态解析与二次确认，是为了延续现有 V2EX 收藏动作的 CSRF/同源安全原则，避免硬编码一次性值或把 200 页面误认为成功。

### 6. 服务端事实优先，本地状态只负责节流和展示

协调对象持有每来源的 in-flight Task，拒绝同来源并发执行。成功确认后在当前服务端周期内跳过重复检查；普通失败采用有上限的前台重试窗口。服务端周期边界只能依据真实响应或被证实的站点规则：V2EX 可以采用其已确认的 UTC 日界线，NGA 在采样前不假设时区。

持久化仅保存每来源开关和不含凭证的安全状态摘要。若无法把成功记录可靠地绑定到当前账号，则冷启动仍查询服务端，而不使用跨账号的“今日已签”缓存跳过检查。登录、退出或网页会话更换会清除相应来源的内存节流状态。

### 7. 默认关闭、非阻塞、失败分级展示

NGA 与 V2EX 各有独立偏好，默认关闭。用户启用后，签到任务与首页加载并行但不参与首页成功条件。成功和已签到只更新账户页摘要；离线、超时、5xx 和未知结构不弹启动提示。只有明确可操作状态（例如 V2EX 缺少 Web 登录）在账户页提供引导。

选择显式 opt-in，是因为签到会修改第三方账号状态；选择账户页状态而不是启动 Toast，是为了避免每日正常行为干扰阅读入口。

## Risks / Trade-offs

- [远端响应或 HTML 改版] → Fixture 驱动严格解析，未知结构停止写入，并允许用户手动访问原站。
- [多设备同时签到] → 服务端状态为权威，已完成视为正常结果；本地缓存不承担全局锁职责。
- [NGA 频率限制或未知日界线] → 先采样 `get_stat`，未确认前不实现日期推断或重复写。
- [V2EX `once` 被错误或恶意链接替代] → 严格校验 scheme、host、path、参数和当前页面来源，拒绝跨域及意外动作。
- [网页登录 Cookie 与 Token 账号不同] → 签到资格只来自 Web Session，不用 Token 用户名给签到结果归属；UI 明确所需会话类型。
- [前台事件过多产生额外网络请求] → 进程内 Task 去重、成功周期缓存及失败退避；不绑定来源切换和普通 Feed 刷新。
- [自动行为违反用户预期] → 每来源默认关闭、可独立停用，且不在后台运行。
- [采样泄漏个人数据] → 原始响应只放非提交 workDir，仓库仅提交人工复核后的脱敏 Fixture；提交前搜索 Cookie、UID、用户名、余额和动态令牌。

## Migration Plan

1. 先落地 fail-closed 纯解析器、请求构造器、可注入服务接缝及明确标注来源的合成/公开文档驱动 Fixture。
2. 添加协调、节流、偏好、应用生命周期和账户 UI；每个来源默认关闭，且未经真实证据确认的未完成状态不可到达写请求。
3. 在后续服务端周期采集并审查真实响应，校准两站状态机、成功判据、日界线和安全动作形状。
4. 在真机使用测试账号分别验证未签到、已签到、离线、Cookie 失效和重复前台进入，确认后才解除真实写入与最终验收门禁。
5. 若远端合约不稳定或真机验证失败，保持开关关闭并禁用对应来源写入；阅读和现有登录流程不受影响。

## Open Questions

- NGA 当前 `get_stat` 是否直接提供服务端日期/周期标识，以及具体成功和频率限制字段是什么？
- NGA `app_api.php` 在有效 Cookie 会话下仍对 `get_stat` 与 `check_in` 返回相同 `code=2`；它是否要求 `Nga_Official`、Referer、特定 HTTP method、设备参数或其他官方客户端合约？在确认前不得把 `app_api.php` 或该 code 纳入 production policy。
- V2EX 失效 Web Session 当前是否稳定重定向到 `/signin`，完整 3xx 链和最终 MIME 形状是什么？
- V2EX Web Session 是否能安全解析出账号标识用于状态归属，还是只展示来源级临时结果？

以上问题必须由真实响应采样回答；在答案补齐前可以完成安全接缝和 fail-closed 路径，但不能凭历史资料或合成 Fixture 解锁生产写入。
