## Why

ForumHub 已能恢复 NGA 与 V2EX 登录会话，但用户仍需离开应用或手动进入站点领取每日签到奖励。应用需要在启动或回到前台后，基于各来源真实且有效的会话安全地完成一次每日签到检查，同时避免重复请求、错误识别登录失效或依赖未经验证的远端响应结构。

## What Changes

- 新增 NGA 与 V2EX 独立的每日签到能力，在应用启动以及经过节流的前台恢复后运行，不阻塞首页加载。
- 交付首先采集两站当前登录态下的真实响应，完成脱敏并固化为测试 Fixture；在响应语义未被确认前，不实现远端签到写操作。
- NGA 使用现有 Cookie 会话检查签到统计，仅在服务端明确表示今日未签到时调用签到动作。
- V2EX 仅使用已验证的 Web Cookie 会话访问每日奖励页面；动态解析并严格校验同源、预期路径且带非空 `once` 的领取动作，不使用 Personal Access Token 代替网页会话。
- 新增进程内并发去重、本地节流与服务端状态确认；本地记录仅用于减少请求，不能替代服务端事实。
- 为 NGA 和 V2EX 提供独立的自动签到偏好，默认关闭，由用户明确启用。
- 在账户界面提供每个来源的最近签到结果及必要的可操作提示；普通网络失败保持静默，不将其误判为会话过期。
- 不增加后台定时任务，不承诺应用未运行时按日历时间签到，也不改变 LINUX DO 行为。

## Capabilities

### New Capabilities

- `source-daily-check-in`: 定义 NGA 与 V2EX 在应用启动/前台恢复时的自动签到触发条件、来源会话要求、真实响应证据门禁、幂等与重试规则、安全校验及用户可见状态。

### Modified Capabilities

无。

## Impact

- 会影响 `ForumHub/ContentView.swift` 的启动与 `scenePhase` 前台协调，但签到必须保持为会话恢复之后的独立远端动作。
- 会扩展 `ForumHub/Session` 中 NGA Cookie 会话与 V2EX Web Session 的来源专属能力，不合并 Token 与 Cookie 身份语义。
- 会新增来源专属响应解析、脱敏 Fixture 和对应单元测试，并在账户界面增加偏好与状态展示。
- 会访问 NGA `app_api.php` 签到接口以及 V2EX `/mission/daily` 网页流程；两者均属于可能变化的远端合约，解析失败必须 fail closed。
- 不引入新的第三方依赖，不改变共享帖子领域模型、Feed Repository 合约或其他数据源能力。
